# Documentation

## Game design

- `game-design/` — gameplay rules, vehicles, combat, maps, matchmaking, progression, economy, and interface.

## Technical

- `technical/` — client, server, networking, persistence, security, replay, and performance specifications.

## Architecture

- `architecture/` — system boundaries, data flow, sessions, and deployment concepts.

## Decisions

- `decisions/` — Architecture Decision Records (ADRs) for important choices and trade-offs.

## Development

- `development/` — local setup, workflow, testing, release process, and developer tooling.

## Security

- `security/` — threat model, trust boundaries, anti-cheat principles, and secure development rules.

## Balancing

- `balancing/` — balance methodology, experiments, metrics, and validated tuning decisions.

## Documentation rule

The repository is the source of truth for project decisions once they are formally recorded. Conversation discussions can propose or refine ideas; stable decisions should be transferred into the appropriate document.
